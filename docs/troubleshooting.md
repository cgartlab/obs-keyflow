# obs-keyflow 故障排查

先看日志：`%LOCALAPPDATA%\obs-keyflow\logs\keyflow.log`（自动轮转，512 KB × 3）。

## 画面上什么都没有

| 检查 | 做法 |
| --- | --- |
| 服务是否在跑 | 浏览器打开 <http://127.0.0.1:16900/healthz>，应返回 `{"service":"obs-keyflow",...}` |
| 端口是否被占 | `Get-NetTCPConnection -LocalPort 16900 -State Listen` |
| 源是否可见 | OBS 里「按键显示」源左侧眼睛图标是否打开，图层是否在最上层 |
| 页面是否连接 | 源属性里 URL 后加 `?debug=1`，画面左上角出现绿点=已连上，红点=没连上 |
| 是否按键被吞 | 在记事本里敲几个键，看是否出现 |

**服务没运行时，源会显示为空白**（页面由服务提供），不会出现报错白页。

## OBS 里没有「按键显示」源

场景集合被重置/切换过。关闭 OBS 后重新注入：

```powershell
python scripts/add-obs-source.py
```

加 `--scene "场景名"` 指定其他场景，`--dry-run` 只预览。

## 弹出「插件加载失败」

obs-keyflow 不使用任何 OBS 插件，出现这个提示说明是**别的插件**在报错：

1. 看 OBS 日志 `%APPDATA%\obs-studio\logs\` 里 `not loaded` / `failed to open` 那一行，路径就是罪魁
2. 常见原因是插件为其他 OBS 版本编译（例如 input-overlay 5.x 需要 OBS 33，而 OBS 32 会失败）
3. 删掉该路径下的插件文件夹即可，OBS 启动就不再提示

本仓库曾试过原生插件方案，结论记录在 README「为什么不写成 OBS 插件」。

## 某些按键不显示

- **管理员权限窗口里的按键**：非管理员进程的键盘钩子收不到更高完整性级别的输入（Windows UIPI 限制）。
  需要覆盖这些窗口时，服务与 OBS 都要以管理员身份运行。
- **游戏全屏独占 + 反作弊**：部分游戏会屏蔽全局钩子；改用无边框窗口模式通常可解。
- **输入法组合过程**：物理按键仍会上屏，显示的是按下的物理键，而不是上屏汉字。

## 组合键显示不对

`Ctrl+C` 显示成两枚键帽，通常是旧版页面缓存。选中源 → 属性 → 点「刷新页面（不使用缓存）」。

## 屏幕上残留一个按键（键帽一直亮着）

根因是**状态失同步**：某枚键帽处于"按住"状态，而对应的 keyup 事件因为断线、事件积压或服务重启没送到页面。

现在内置三层自愈，正常情况下不需要人工干预：

1. **服务端**：每秒用 `GetAsyncKeyState` 核对物理键，早已松开的会自动释放
2. **事件积压**：客户端队列满时不再丢事件，而是改发一份全量快照（`snap`），页面收到后整体校正
3. **客户端**：每 2 秒向 `/state` 核对一次，对不上的"按住"立即释放；服务不可达则直接清屏；
   另有 `?hold=`（默认 60 秒）兜底，单枚键帽不会无限期保持按住

仍想加一道保险可以开自动刷新缓存：

- 源 URL 加 `?reload=30`：每 30 分钟（仅在画面上没有键帽时）强制重载页面，避免旧缓存
- 或在 OBS 源属性里勾选「当场景激活时刷新页面」（每次切到该场景都重载）

诊断：`http://127.0.0.1:16900/healthz` 里的 `resyncs` 若持续增长，说明事件积压确实发生过（已自动补发快照，不影响显示）。

## 键帽停留时间不合适 / 不消失

- 默认每枚键帽 **3 秒后淡出消失**（最后 0.45 秒渐隐），整条胶囊随之隐去
- 想停留更久：URL 加 `?ttl=5000&fade=800`；想更快消失：`?ttl=1200`
- **按住不放**的键会一直保持高亮，且按住期间不计时——松开后才开始 3 秒倒计时
- 若长时间不消失且你并没有按键，检查日志里的「自愈」记录，或重启服务

## 锁屏 / 登录界面时按键不显示

这是预期行为，不是故障：Windows 在锁屏和安全桌面（UAC 提权弹窗）里使用**独立的输入桌面**，
普通用户进程的低层键盘钩子收不到那里的按键，`GetForegroundWindow()` 也会返回 0。

- 判断方法：任务管理器里出现 `LogonUI.exe` 即为锁屏状态
- 解锁回到桌面后按键立刻恢复，不需要重启服务
- 如果你要录锁屏画面（少见），那部分按键本来就无法显示

## 鼠标拖不动按键

按可能性依次排查：

1. **源被锁定了**：源列表里该项带「锁」图标，或右键 →「解锁」。锁住的源在预览里拖不动（`add-obs-source.py` 默认会写成未锁定）
2. **还是旧的全画布源**：铺满 1920×1080 的源拖起来会连着整块画布一起动，很难对准。重跑
   `python scripts/add-obs-source.py` 换成 880×160 的紧凑部件源（记得先关 OBS）
3. **OBS 窗口不在最前**：被其他窗口压住时点不到预览，先把 OBS 切到前台
4. **拖到了别的图层**：铺满画布的「显示器采集」在下层，如果没选中「按键显示」，拖的其实是它。
   先在预览里点一下按键本身（选中后再拖）
5. **开了吸附**：拖动时会吸附到画布中线/边距，属正常；要微调可在「变换」里直接改位置 X/Y

## 部件模式拖动后键帽变小

说明内容比浏览器源框还宽/高，页面自动等比缩小了。把源的宽度/高度调大（或减少键帽数 `?n=`、尺寸 `?size=`）即可恢复原大小。

## 键帽位置不对 / 想贴边

- 默认底部居中、距底 44px；想贴右下角：`?anchor=br&margin=60`
- 九宫格写法：`tl` `tc` `tr` / `ml` `c` `mr` / `bl` `bc` `br`，也接受 `top-left`、`right`、`center` 等英文写法
- 完整列表见 README「吸附位置速查」；改完参数记得点源属性的「刷新页面」
- 锚点写错时会回退到 `bc` 并在控制台打警告，不会跑到画面外

## 开机后不自动启动

```powershell
.\scripts\install-autostart.ps1     # 重新安装
```

或检查 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\obs-keyflow.lnk` 是否存在。

## 录制文件比录制时长短很多

先看 OBS 日志里有没有 `output simple_file_output paused` / `unpaused`：
录制被暂停过的话，文件里只包含真正在录的片段（例如 16:04 开始、16:06 暂停、17:54 继续再停，
文件只有约 2 分钟是正常现象），不是丢帧也不是编码问题。

## 端口 16900 冲突

改端口启动：`python -m keyflow --port 17000`，并把 OBS 源的 URL 改成新端口。
（默认端口写死在 URL 里，换端口后需同步改源属性。）

## 日志里出现「自愈: 释放 N 个残留按键」

这是正常保护：说明有一次按键抬起事件丢失，服务根据物理键状态自动纠正。频繁出现时检查是否在用远程桌面 / 切换用户 / 睡眠唤醒。
